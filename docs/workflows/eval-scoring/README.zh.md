# 交接评测打分

English: [README.md](README.md)

每个模型得到一个 0–1 的分数：**总分 = 0.5 × 完成度 + 0.5 × 质量**，每个数字都带 95% 置信区间。
区间宽窄由试次数量决定：10 次试验的区间很宽，只有两个模型的区间不重叠，才能说它们真的不同。规则于 2026-10-23 和用户确认；
2026-11-14 起所有打分只用一套阶段，即 9 个 `fine9` 阶段（用户："分数用哪套阶段就按照哪个打分"）。

```bash
python docs/workflows/eval-scoring/report.py <out_prefix> <human_ref_demo_dir> <dataset_dir> ...
```

- `human_ref_demo_dir`：人类示范基准，目前是 `wwqcleverghost/v4-handover2-trimmed`。
- `dataset_dir`：评测数据集（有 `success.csv`）和/或示范数据集（只算质量）。嵌套在 `dataset/` 里的也可以。
- 输出 `<out_prefix>.csv`（每个数据集一行，所有分数和区间）和 `<out_prefix>.svg`（每个数据集一根叠加柱：
  蓝色 = 0.5 × 完成度，橙色 = 0.5 × 质量，细线 = 总分的置信区间；示范数据集的完成度画成虚线框、按 1.0 计，方便对比）。
  结果放在 `outputs/eval_scores_<date>/`，示例见 `outputs/eval_scores_20261023/`。
- 读 `observation.state`、`action` 和每个数据集的 `episode_end.csv`（阶段和任务结束点，由 `mark_end.py` 写，见下）。
  缺这个文件时 `report.py` 先生成它，这一步要把腕部视频解码一遍。lerobot 环境即可（不需要 matplotlib）。

## 阶段

打分和显示只用一套阶段：[`../stage-labels/`](../stage-labels/README.zh.md) 的 9 个 `fine9` 阶段，
A前往、A对位、A抓住、A抓着、AB对位、B抓住、B抓着、B放下、复位（第 0 到第 8 阶段）。逐帧阶段：用当前规则从腕部视频离线重算 `fine9`
（2026-11-17 起，写了 `stages.csv` 的评测也重算：那是模型当时看到的、评测当天规则的阶段；2026-11-17 的"碰到"规则见 [`../stage-labels/README.zh.md`](../stage-labels/README.zh.md)）。`mark_end.py` 把每条走到的最远阶段（`top_stage`）和任务结束点
（复位的第一帧）存进 `episode_end.csv`。

## 完成度（只有评测有）

- **进入**某个阶段 = 走到的最远阶段是它或它之后的阶段；**通过** = 进入了下一个阶段。最后一个阶段（复位）通过 = 人工标成功。
- **人的判断是最终结果**（不用看视频）：标成功 → 9 个阶段全过。标失败，并且网页工具里这条的备注写了某个阶段
  （`AB对位失败`：阶段名后面跟"失败"；a、b 小写也算）→ 走到了该阶段、没有通过。标失败又没有这样的备注 → 按规则看到的最远阶段。
  规则会把夹爪空抓读成后面的阶段，所以没写备注的失败试次可能被多算：要写备注。
- **阶段通过率 = (通过 + 1) / (进入 + 2)**。没进入某个阶段的试次不算这个阶段失败。
  +1/+2 让样本少的阶段往 0.5 靠（1/2 变成 0.5，7/7 变成 0.89），避免一两次样本就拿到极端分数。
- 每个阶段通过率都做**截断**：<= 0.5 记 0 分，1.0 记 1 分，中间按比例换算。完成度 = 9 个截断后通过率的平均。
- 另外报告、但不计入分数：整体成功率（如 7/10）及 Wilson 置信区间；每个阶段的 `通过/进入 [区间]`（漏斗，看出模型卡在哪一步）。

## 质量（评测和示范数据集都有）

逐试次加权，和人类基准的中位数比较：
- **平滑（0.4）**— 运动中每秒的小幅关节来回次数（`smooth.py`：死区 0.5，摆幅 < 5）
- **速度（0.3）**— 从开始动到任务结束（复位的第一帧）的用时；只算成功且走到复位的试次（成功但规则没找到复位的没有用时）
- **不停顿（0.3）**— 从开始动到任务结束之间站着不动（< 5 单位/s 且持续 >= 0.5 秒）的时间占比；
  没走到复位的试次算到它的 `still` / 录制结束点

人类基准用同样的口径量；示范数据集里一条走到复位就算完成。

平滑和速度：**和人类中位数一样或更好记 1 分，差 2 倍记 0.5 分，差 4 倍记 0 分**（每差一倍扣一半）。
不停顿 = 1 − 停顿占比，和阶段通过率一样截断。人类示范自己大约 0.9 分（一半示范比它们自己的中位数差），
这个分数不能和其他项目的数字直接比较。

## 不确定性

阶段通过率和成功率：Wilson 95% 置信区间。完成度、质量、总分：按试次自助抽样（2000 次，取 2.5–97.5 百分位）。
10 次试验分不出 7/10 和 4/10（Fisher p ≈ 0.37）；区间重叠时要说明，宁可给前几名模型多测几次，也不要把打分做得更细。

## 可选：挑评测试次当训练数据（极严，2026-10-23 用户同意加）

只保留每一项都不比人类示范差的成功试次，以下全部满足才保留：
1. 人工标成功，并且规则看到这条走到了复位（`top_stage` 为 8）；
2. 不重抓：每只手臂夹爪闭合不超过 2 次（不用"抓住次数"，因为一次抓取常被拆成两段，人类示范也这样）；
3. 质量三项全是 1 分：平滑、速度都不比人类中位数差，任务中没有停顿；
4. 数据集整理清单：最后一帧头部画面桌上看得到胶带，先抓的手臂符合中线规则（L x<=0.49，R x>=0.51）。

开始时胶带是否立着单帧判不准，保留下来的试次要用 `sheets.py` 看一眼。

```bash
PYTHONPATH=src:docs/workflows/eval-scoring:docs/workflows/handover-dataset-curation:examples/xlerobot \
  python docs/workflows/eval-scoring/select_strict.py <out_prefix> <human_ref_demo_dir> <eval_dir> ...
```
输出 `<out_prefix>.csv`（每个试次每项是否通过）和 `<out_prefix>_spec.json`（给 `trim_stagnant_frames.py --spec` 用）。
评测数据是 12 维（没有头部舵机和底盘），不能和 17 维的人类示范放进同一个 spec。

## 每条的阶段和任务结束点（`mark_end.py`）

试次是人按键结束的，会早几秒或晚几秒。`mark_end.py` 给评测或示范数据集写 `<数据集目录>/episode_end.csv`
（episode, end_frame, frames, how, top_stage），不截断任何数据。`top_stage` = 所有帧里最高的 `fine9` 阶段（只是规则的结果，
不含人工标签）。分数读这个文件，所以改了阶段规则或手改了阶段起点（`stage_edits.json`）之后要重跑：

still = 从这一帧起所有手臂关节（指令和从臂）都在最后姿态 3 个单位以内：机器人已经停了，之后是在等人按键。

走到复位的试次（fine9 第 8 阶段，用腕部视频离线重算）结束点取复位开始（用户 2026-11-06）：
很多试次复位没做完就被结束了，算到复位开始是所有试次都有的一段。

- `reset`：结束 = 复位段第一帧。

其他试次：

- `still`：结束 = still。
- `human`：一直动到最后 0.5 秒内；结束 = 录制长度。

数据集网页的"阶段 / 进度"页画出这个结束点，之后变灰。2026-11-14 起质量分用它作任务结束点。

```bash
PYTHONPATH=src python docs/workflows/eval-scoring/mark_end.py ~/.cache/huggingface/lerobot/wwqcleverghost/eval-v8-flow_h16_s8
```
