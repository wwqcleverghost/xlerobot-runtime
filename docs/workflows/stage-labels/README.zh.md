# 阶段标签

English: [README.md](README.md)

给交接（handover）录像的每一帧标上任务阶段，用作模型的额外输入（`observation.environment_state`），让模型知道"做到哪一步了"，
不再把开头和结尾搞混。代码：[`examples/xlerobot/stage_labels.py`](../../../examples/xlerobot/stage_labels.py)；
网页工具顶栏"阶段"下拉框可以直接看（[`../dataset-viewer/README.zh.md`](../dataset-viewer/README.zh.md)）。
评测打分的 5 阶段（`score.stage_frames`，见 [`../eval-scoring/README.zh.md`](../eval-scoring/README.zh.md)）在这里是规则 `eval5`。

**用法总结**：给训练集加标签 → 用 `<名字>-stagelabel` 训练 → 真机评测时脚本**自动**实时算阶段喂给模型（见"评测"）。
规则一改，已经加过标签的数据集要重新加一次（见"写进数据集"），否则训练标签和评测时算出来的不一致。

## 约定

- **A** = 第一个夹住胶带的手臂，**B** = 另一只。
- 每个阶段边界是一个事件。每个事件只定义一次，只用当前和过去的帧就能判断；它有两个时刻：
  **确认**（证据够了的那一帧）和**起点**（往回找到的证据第一帧）。
- 第 t 帧用的是第 t 帧的从臂状态和**第 t−1 帧的指令**（第 0 帧用状态）：数据集里第 t 帧的动作是看到第 t 帧之后才决定的，
  真机上做决定时只知道上一帧发出的指令。
- 夹爪数值：约 1 = 合上没东西，约 30 = 张开；夹着胶带时读数约 7–12。
  "合拢 / 松手"看主臂指令（`action`），"夹住 / 张开到位"看从臂状态（`observation.state`）。
- 胶带直径 = 腕部相机画面里黄绿色胶带像素（PIL HSV：色相 28–80 / 255，饱和度 > 70，亮度 > 60；缩到 160×120 再算）
  横向和纵向范围（2%–98% 分位）里较大的那个，占画面宽度的比例。夹爪会挡住胶带中间，但很少挡住边缘，所以比面积稳定。
- 夹爪尖位置用正运动学从关节读数算（[`examples/xlerobot/xlerobot_fk.py`](../../../examples/xlerobot/xlerobot_fk.py)，见下文"正运动学"）。

## 9 个阶段

| # | 阶段 | 开始事件 | 起点 / 确认 | 看视频怎么认 |
|---|---|---|---|---|
| 0 | A前往 | 开头 | | 手臂朝胶带移动，胶带在腕部画面里还小 |
| 1 | A对位 | **E0**：某只手腕部画面里胶带直径 ≥ 0.18（抓取时直径的一半），且该手夹爪**张开到位**（读数 > 10 且不再变化，读数变化 < 1） | 连续 5 帧满足的第一帧 / 第 5 帧 | 夹爪已经张开、胶带很近，在对准 |
| 2 | A抓住 | **E1**：某只手开始合拢、**并且末端基本不动**（夹爪尖最近 5 帧**沿夹爪轴线（腕 → 夹爪尖，约等于腕部 z 轴）**的速度 < 2 cm/s；沿桌面横向滑动不算，如 v8 ep32），取两者中较晚的；先满足的那只就是 A。还在往下对位时就合夹爪不算 | 合拢起点（指令比这一次张开的峰值低 2 以上）和末端停下的那一帧中较晚的 / 指令低 5 以上且已静止 | 末端停住、夹爪正在合上 |
| 3 | A抓着 | **E2**：A 夹住 = 夹爪读数取 5 帧平均后，平均值在胶带宽度（4–20）、5 帧内变化 < 0.5（小抖动被平均掉）、指令没有要它张开（指令 < 读数 + 2） | 读数稳定下来的那一帧 / 确认那一帧（约晚 9 帧） | A 拿着胶带 |
| 4 | AB对位 | **E3**：B 进入 A 腕部相机的视野 = B 的夹爪尖和 A 的夹爪方向（腕 → 夹爪尖）夹角 < 35° | 连续 5 帧满足的第一帧 / 第 5 帧 | B 出现在 A 的腕部画面里 |
| 5 | B抓住 | **E4**：B 开始合拢（同 E1 的合拢，**不要求末端静止**：B 是迎上去的），且这次合拢之前 B 张开过（指令峰值 ≥ 15；半张着合一下不算，如 v8 ep26 f234 峰值只有 11）。A 在 B 合拢途中松手也算（交接进行中） | 这次合拢的起点 / 指令比峰值低 5 以上 | B 正在合拢 |
| 6 | B抓着 | **E5**：**B 夹住**（同 E2，并且读数比合拢开始时低 2 以上）。不等 A 松手：A 的松手落在 B抓着 里（A 松手 = A 的指令比它夹得最紧时的读数大 4 以上且 > 10，**轻微松一下不算**） | 读数稳定下来的那一帧 / 确认那一帧 | B 拿着胶带，A 松开，移向放置点 |
| 7 | B放下 | **E6**：B 松手（同 A 松手的定义，对 B） | 指令连续高于（松手阈值 − 2）那一段的第一帧（之前的轻微放松不算）/ 超过阈值那一帧 | 松手放下胶带 |
| 8 | 复位 | **E7**：B 松手后手臂**开始朝初始姿势回收** = B 的关节离初始姿势（这条录像第一帧）的距离连续 5 帧每帧都在变小，累计至少 2（读数单位）。松手后先抬起、移开不算，夹爪合不合拢也不看 | 这段连续变小的第一帧 / 第 5 帧 | 两臂往回收 |

夹紧不要求"指令比读数低很多"：夹住胶带后操作者经常把主臂放松到和读数差不多（约 10）。读数 ≤ 4 是合到底（空的），
约 30 是电机还没开始动，都被 4–20 排除。

## 失败（不设失败标签；阶段只增不减）

一条录像里阶段编号**不会下降**。唯一的例外是胶带确认掉了：机器人运行时必须知道要重新去拿，否则胶带在桌上、阶段却还是"A抓着"。

| 情况 | 判定 | 阶段 |
|---|---|---|
| A 没抓住 / 合到一半又张开重来 | | 停在 A抓住，直到夹紧 |
| B 没夹住 / 重来 | | 停在 B抓住，直到 B 夹住 |
| A 抓着时掉了 / 没交接就松手 | A 合到底（读数 ≤ 4，连续 5 帧），或 A 松手时 B 还没开始合拢 | 回到 A前往（A、B 重新认定） |
| 交接时掉了 | A 已经松手而 B 合到底 | 回到 A前往 |
| 交接后 B 掉了 | B 合到底 | 回到 A前往 |
| 录像结尾被裁掉 | 没有后续事件 | 停在最后那个阶段 |

回到 A前往 之后，只认之后才开始的合拢（之前那次合拢不能马上又算成新的抓取）。
A 在 B 开始合拢之后、B 夹紧之前松手：仍是交接，停在 B抓住 等 B 夹紧。

## 两个规则：同一套事件

- **`fine9`**：在**确认**时刻切换阶段，机器人运行时能算出一模一样的结果（`StageTracker.step`，评测用 `LiveStage`）。**训练输入用它**：
  测试时机器人只能算 `fine9`，训练输入要和测试时一样；用 `std9` 训练，模型会学到比测试时早几帧的阶段。网页下拉框里只有它。
- **`std9`**：同一串事件，切换放在**起点**。用来核对（人工对照视频、`--compare`），以及以后阶段作为**训练目标**时
  （例如训练 SARM 或阶段分类器）用它。两个规则阶段顺序完全相同，差别只是每个边界晚几帧。

## 正运动学

[`examples/xlerobot/xlerobot_fk.py`](../../../examples/xlerobot/xlerobot_fk.py) 由关节读数算两只手的腕部和夹爪尖位置（右臂底座坐标系，x 前、y 左、z 上）：

- 单臂结构：TheRobotStudio/SO-ARM100 的 `so101_new_calib.urdf`（commit 385e8d7c68，2025-07-02），零位 = 每个关节活动范围的中点，和 LeRobot 校准一致。
- 读数换算：录制时 `use_degrees=False`，读数是 -100…100（0 = 校准范围中点），角度 = 读数 / 100 × 半个范围（刻度）× 360° / 4096。
  范围来自实验室电脑上的校准文件 `xlr26009.json`（2026-08-20）。
- 左臂底座位置：用交接时两只手都夹着胶带的帧（A 松手前 10 帧）拟合，得到 (-1.9, 24.3, 0.3) 厘米，两底座朝向相同；
  XLeRobot 整机模型 `xlerobot.urdf` 写的是相距 26.6 厘米、同高同朝向。此时两个夹爪尖相距中位数 4.9 厘米（两只手夹在胶带两侧）；
  把肩抬 / 肘 / 腕屈的正负号反过来会变成 18 厘米，所以正负号是对的。
- 视野：A 的腕部相机近似成以腕部为顶点、沿夹爪方向的圆锥（和末端坐标系 z 轴差约 4.6°），只检查 B 的夹爪尖。
  看 v7 ep3、ep20、ep33 的腕部画面，B 出现时夹角在 25–32° 之间；最初取 30°，但 v8 ep26、ep38 的 B 在合拢前最近只到 33.5–34°，
  AB对位 被跳过，所以放宽到 35°（其他录像的 AB对位 起点平均只提前 0.2 秒，90% 在 1 秒以内）。相机装在夹爪上方斜着看，所以比相机实际视场角小。

## 手动修正

规则判错的地方可以在网页工具里手动拖阶段起点（顶栏"改阶段"，见 [`../dataset-viewer/README.zh.md`](../dataset-viewer/README.zh.md)），
存在 `examples/xlerobot/stage_edits.json`。`apply_edits` 只移动该阶段第一段的起点，限制在前后两段之内（不会让阶段消失；要挪过下一段的起点，先把后面的阶段往后挪）；
`add_stage_labels.py` 写标签时套用，`--compare` 和 `std9` 不套用。
代价：真机评测时 `LiveStage` 照规则实时算，遇到同样的情况仍会判成规则的结果，所以手改的地方训练标签和评测输入不一致。
规则能修的优先修规则，手改只用于个别录像。

## 写进数据集

训练只读数据集自己的文件，所以阶段要写成数据集里的一列：
[`examples/xlerobot/add_stage_labels.py`](../../../examples/xlerobot/add_stage_labels.py) 把 `fine9` 的 9 维 one-hot 写成
`observation.environment_state`（**原地修改**：只改 `data/*.parquet`、`meta/info.json`、`meta/stats.json`，视频不动；先把 `data/`、`meta/`
备份到 `<owner>/_trash_<日期>/`），然后把数据集改名为 `<名字>-stagelabel`。对已经有这一列的数据集再运行一次 = 按当前规则重新计算（不改名）。
diffusion 不归一化 ENV 类型的输入，one-hot 原样进模型；数据集里有这一列，diffusion 训练就会自动把它当输入。

```bash
PYTHONPATH=src python examples/xlerobot/add_stage_labels.py --dataset v8-handover2              # 加列并改名为 v8-handover2-stagelabel
PYTHONPATH=src python examples/xlerobot/add_stage_labels.py --dataset v8-handover2-stagelabel   # 规则改了以后重新计算
```

## 评测

真机评测时模型需要每一帧的阶段。`lerobot_record_eval.py` 和 `examples/xlerobot/eval_remote_trials.py` **自动**处理：
模型的输入里有 `observation.environment_state` 时（用 `*-stagelabel` 训练的模型），每一帧用 `stage_labels.LiveStage`
（关节读数 + 两路腕部画面 `left_wrist` / `right_wrist` + 上一帧发出的指令）算出 `fine9` 阶段喂给模型，启动时打印
`Stage input on: ...`。人工接管期间也照常更新，交还模型时阶段是最新的。阶段只喂给模型，不写进录下的测试集（测试集可以用同样的规则离线算）。
不需要额外参数；没看到 `Stage input on` 就说明模型没有这个输入。

## 命令行

```bash
PYTHONPATH=src python examples/xlerobot/stage_labels.py --dataset v8-handover2-stagelabel [--rule fine9|std9|eval5] [--episodes 0 1] [--compare]
```

`--compare`：把 `--rule` 和 `std9` 逐条比较，打印逐帧一致率和进入每个阶段晚多少帧。腕部相机的胶带直径第一次算要解码两路视频
（每条约 6 秒），缓存在 `outputs/dataset_viewer/cache/tape/`，和网页工具共用。
